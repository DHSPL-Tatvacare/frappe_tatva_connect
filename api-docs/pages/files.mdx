title: Files

A file is a document attached to a [lead](/leads), or to one of the lead's [activities](/activities) or [notes](/notes). Every file is scanned for malware before it's stored.

## Operations

All file endpoints start with `$BASE_URL/api/method/tatva_connect.api.partner_file.` The [API Reference](/partner-api) lists every parameter and has a playground for each one.

| Operation | Method | Endpoint | What it does |
|---|---|---|---|
| Schema | `GET` | `file_schema` | Lists the file fields. |
| Get | `GET` | `file_get` | Reads one file by `name`, with a link to download it. |
| List | `GET` | `file_list` | Deprecated. Use `file_get_bulk` with filters. |
| Attach | `POST` | `file_attach` | Uploads a file and attaches it. |
| Update | | | Files have no update. See [Update](#update). |
| Delete | `DELETE` | `file_delete` | Deletes a file by `name`. |
| Get many | `POST` | `file_get_bulk` | Reads up to 200 files by `name`, or a page of files that match filters. |
| Attach many | `POST` | `file_attach_bulk` | Uploads up to 5 files. |
| Delete many | `DELETE` | `file_delete_bulk` | Deletes up to 25 files by `name`. |

## Identity

- Each file has a **unique ID** in `name`. Store it. You need it to read or delete the file, and to get a new download link.
- The CRM doesn't check for duplicates. If you attach the same file twice, you get two files. To retry an attach safely, send an `Idempotency-Key` header. See [Writes and retries](/writes-and-retries).
- `external_id` is your own label for the file. The CRM never uses it to find a file. See [Keywords](/keywords).

A file is attached to a lead by default. To attach it to one of the lead's records instead, send that record's `name`:

| Send | The file is attached to |
|---|---|
| `lead` or `mobile_no` only | the lead |
| `activity` | that activity |
| `note` | that note |

Send `activity` or `note`, not both. The activity or note must belong to the same lead. If it doesn't, the API returns `404 not_found`.

## Fields

`file_schema` lists the file fields:

```bash title="Request"
curl -s "$BASE_URL/api/method/tatva_connect.api.partner_file.file_schema" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  | jq -r '.data.fields[] | "\(.fieldname)\t\(.behavior)"'
```

| Field | What it holds |
|---|---|
| `filename` | The file's name, with its extension, such as `report.pdf`. Required. |
| `content_base64` | The file's bytes, base64-encoded. |
| `file_url` | A public `http` or `https` link that the API downloads the file from. |
| `lead` | The lead's `name`. |
| `mobile_no` | The lead's phone number, used only to find the lead. |
| `activity` | An activity's `name`, such as `1024`, to attach the file to it. The activity must belong to the same lead. |
| `note` | A note's `name`, such as `n4b8c2d6e1`, to attach the file to it. The note must belong to the same lead. |
| `file_type` | Your own label for the kind of document, such as `Lab Report`. You can filter `file_get_bulk` by it. |
| `external_id` | Your own label for the file. |

Send the bytes in one of two ways: `content_base64` or `file_url`. If you send both, the API uses `file_url`.

## Create

Use `file_attach`:

```bash title="Request"
curl -X POST "$BASE_URL/api/method/tatva_connect.api.partner_file.file_attach" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: <a-new-uuid-per-file>' \
  -d '{
    "lead": "a7f3c9e12b",
    "external_id": "REF-1001",
    "file_type": "Lab Report",
    "filename": "hba1c-2026-05.pdf",
    "content_base64": "<base64-of-the-file>"
  }'
```

```json title="Response"
{
  "status": "success",
  "action": "created",
  "data": {
    "name": "c2dca7b4a6",
    "file_type": "Lab Report",
    "external_id": "REF-1001",
    "filename": "hba1c-2026-05.pdf",
    "file_url": "…",
    "expires_at": "…",
    "size": 48213,
    "is_private": true,
    "attached_to": "lead",
    "attached_to_name": "a7f3c9e12b"
  }
}
```

If you send a `file_url`, it must be an absolute `http` or `https` link to a public address, and it must return the file itself. The API refuses links to private or internal addresses. It doesn't follow redirects, so a link that redirects returns `400`. Send the final link.

## Read and list

To read one file, send its `name` to `file_get`. The response has a `file_url` to download the file, and `expires_at`, the time the link stops working. To get a new link, read the file again.

Treat a download link like a password while it works. Don't log it or share it. Store the file's `name`, and get a new link when you need one.

To read many files, send filters to `file_get_bulk` instead of `names`. Send the lead's `name` as `lead`, or its phone number as `mobile_no`. The result includes files attached to the lead's activities and notes. It returns whole files, newest first, and adds `paging` with `total`, `count`, `offset`, `limit` and `has_more`. You can filter by:

| Filter | Returns files |
|---|---|
| `file_type` | of this file type |
| `created_after`, `created_before` | created in this time range |
| `updated_after`, `updated_before` | changed in this time range |

```bash title="Request"
curl -X POST "$BASE_URL/api/method/tatva_connect.api.partner_file.file_get_bulk" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  -H 'Content-Type: application/json' \
  -d '{
    "lead": "a7f3c9e12b",
    "updated_after": "2026-09-01 00:00:00",
    "limit": 200
  }'
```

A page holds 20 files by default and 200 at most. Use `limit` and `offset` to page. Dates follow [Dates and times](/conventions#dates-and-times).

`file_list` takes the same filters and still works, but it's deprecated. Use `file_get_bulk`.

## Update

Files have no update. To replace a file, attach the new one first, and then delete the old one. This way the lead is never without the file.

## Delete

Send the file's `name` to `file_delete`, in the query:

```bash title="Request"
curl -X DELETE "$BASE_URL/api/method/tatva_connect.api.partner_file.file_delete?name=c2dca7b4a6" \
  -H 'Authorization: token <api_key>:<api_secret>'
```

## Bulk

`file_attach_bulk` handles up to 5 files per call, because each file is scanned. `file_delete_bulk` handles up to 25, and `file_get_bulk` up to 200.

| Call | Body key |
|---|---|
| `file_attach_bulk` | `files` |
| `file_delete_bulk` | `names` |
| `file_get_bulk` | `names` |

The API handles each file on its own. The response has a `summary` with the counts, and a `results` array with one entry per file, in the order you sent them. Resend only the ones that failed. By default, a key can make one bulk write every 5 seconds. Bulk reads don't wait for it.

## Rules

| Topic | What to know |
|---|---|
| Size | Each file can be up to 25 MB by default. TatvaCare can raise this limit on request. |
| File type | You can attach PDF, PNG, JPG, CSV, and TXT files. The API checks that each file's contents match its extension, so name each file with its real extension. |
| Malware scan | The API scans every file before storing it. A file that fails the scan isn't stored. |
| Privacy | Files are private. You can only download them with the signed link from `file_get`. |
| Speed | The scan makes an attach slower than other writes, about a second per file. |
| Rate limits | See [Rate limits](/rate-limits) for the default limits, and how to ask for more. |

## Errors

These are the errors you're most likely to see with files. [Errors](/partner-errors) explains the error format.

| Status | Code | When |
|---|---|---|
| `400` | `validation_error` | `filename` is missing. Neither `content_base64` nor `file_url` was sent. The base64 is invalid. The `file_url` points to a private address, redirects, or can't be downloaded. The file failed a check. |
| `404` | `not_found` | The file, lead, activity, or note doesn't exist, or your key can't reach it. |
| `409`, `422` | `conflict` | An `Idempotency-Key` is still in use, or was used with a different body. |
| `429` | `rate_limited` | Your key reached its rate limit. Wait for `retry_after` seconds. |
| `503` | `server_busy` | The malware scanner is unavailable. Nothing was stored. Retry with backoff. |

When the API refuses a file, `error.detail` says why. `check` is `file_screening` for the malware and type scan, or `pdf_structure` for a PDF that can't be read. `verdict` is one of:

| `verdict` | Meaning |
|---|---|
| `Type Not Allowed` | TatvaCare doesn't accept this file type. |
| `Type Mismatch` | The file's contents don't match its extension. |
| `Infected` | The scan found malware. `error.detail.signature` names it. |
| `Scanner Unavailable` | The scanner couldn't be reached. This comes with `503`, not `400`. |
| `Unreadable PDF` | The file is named `.pdf`, but its structure can't be read. Export it again, or name it with the extension its contents really are. |
