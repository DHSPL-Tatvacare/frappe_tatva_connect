A call is a phone call logged against a [lead](/leads). Use calls to record calls your own system made or received, with their direction, time, length, and recording.

## Operations

All call endpoints start with `$BASE_URL/api/method/tatva_connect.api.partner_call.` The [API Reference](/partner-api) lists every parameter and has a playground for each one.

| Operation | Method | Endpoint | What it does |
|---|---|---|---|
| Schema | `GET` | `call_schema` | Lists the call fields. |
| Get | `GET` | `call_get` | Reads one call by `name`. |
| List | `GET` | `call_list` | Deprecated. Use `call_get_bulk` with filters. |
| Create | `POST` | `call_create` | Logs a call. |
| Update | `PUT` | `call_update` | Changes a call by `name`. |
| Delete | `DELETE` | `call_delete` | Deletes a call by `name`. |
| Get many | `POST` | `call_get_bulk` | Reads up to 200 calls by `name`, or a page of calls that match filters. |
| Create many | `POST` | `call_create_bulk` | Logs up to 25 calls. |
| Update many | `PUT` | `call_update_bulk` | Changes up to 25 calls by `name`. |
| Delete many | `DELETE` | `call_delete_bulk` | Deletes up to 25 calls by `name`. |

## Identity

- Each call has a **unique ID** in `name`, for example `PARTNER-3f9a1c7e2b`. Store it. You need it to read, update, or delete the call.
- The CRM doesn't check for duplicates. If you send the same create twice, you get two calls. To retry a create safely, send an `Idempotency-Key` header. See [Writes and retries](/writes-and-retries).
- `external_id` is your own label for the call, such as your telephony system's call ID. The CRM never uses it to find a call. See [Keywords](/keywords).

A call links to a lead in one of two ways:

1. You send the lead's `name` as `lead`, or its phone number as `mobile_no`.
2. You send neither. The CRM then looks for the lead by the customer's phone number: `from_number` for an inbound call, `to_number` for an outbound call.

In the second case, the CRM links the call only if exactly one lead in your product line and group matches. If none or several match, the call is saved without a lead, and your key can't read it again. To avoid this, send `lead` whenever you know it.

For example, Asha calls back from `+919900000000`. You log the inbound call without `lead`. Asha is the only lead with that number, so the CRM links the call to her.

## Fields

`call_schema` lists the call fields. They're the same for every key:

```bash title="Request"
curl -s "$BASE_URL/api/method/tatva_connect.api.partner_call.call_schema" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  | jq -r '.data.fields[] | "\(.fieldname)\t\(.behavior)"'
```

| Field | What it holds |
|---|---|
| `lead` | The lead's `name`. |
| `mobile_no` | The lead's phone number, used only to find the lead. |
| `direction` | `Inbound` or `Outbound`. Required. |
| `from_number` | The number that made the call. Required. |
| `to_number` | The number that received the call. Required. |
| `status` | The call's outcome. If you leave it out, the CRM sets `Completed`. `call_schema` lists the allowed values. |
| `duration` | The call's length in seconds. |
| `started_at` | When the call started, as `YYYY-MM-DD HH:MM:SS` in IST. |
| `recording_url` | A link to the call's recording. |
| `external_id` | Your own label for the call. |

## Create

```bash title="Request"
curl -X POST "$BASE_URL/api/method/tatva_connect.api.partner_call.call_create" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: <a-new-uuid-per-call>' \
  -d '{
    "lead": "a7f3c9e12b",
    "external_id": "CALL-001",
    "direction": "Outbound",
    "from_number": "+919800000000",
    "to_number": "+919900000000",
    "status": "Completed",
    "duration": 180,
    "recording_url": "https://recordings.example.com/call-001.mp3",
    "started_at": "2026-09-20 10:30:00"
  }'
```

```json title="Response"
{
  "status": "success",
  "action": "created",
  "data": {
    "name": "PARTNER-3f9a1c7e2b",
    "external_id": "CALL-001",
    "lead": "a7f3c9e12b",
    "direction": "Outbound",
    "from_number": "+919800000000",
    "to_number": "+919900000000",
    "status": "Completed",
    "duration": 180,
    "recording_url": "https://recordings.example.com/call-001.mp3",
    "started_at": "2026-09-20 10:30:00",
    "creation": "2026-09-20 10:30:00",
    "modified": "2026-09-20 10:34:05"
  }
}
```

Check `data.lead` in the response. If it's `null`, the call wasn't linked to a lead. See [Identity](#identity).

## Read and list

To read one call, send its `name` to `call_get`.

To read many calls, send filters to `call_get_bulk` instead of `names`. Send the lead's `name` as `lead`, or its phone number as `mobile_no`. It returns whole calls, newest first, and adds `paging` with `total`, `count`, `offset`, `limit` and `has_more`. You can filter by:

| Filter | Returns calls |
|---|---|
| `direction` | `Inbound` or `Outbound` |
| `status` | with this status |
| `created_after`, `created_before` | created in this time range |
| `updated_after`, `updated_before` | changed in this time range |

```bash title="Request"
curl -X POST "$BASE_URL/api/method/tatva_connect.api.partner_call.call_get_bulk" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  -H 'Content-Type: application/json' \
  -d '{
    "lead": "a7f3c9e12b",
    "updated_after": "2026-09-01 00:00:00",
    "limit": 200
  }'
```

A page holds 20 calls by default and 200 at most. Use `limit` and `offset` to page. Dates follow [Dates and times](/conventions#dates-and-times).

`call_list` takes the same filters and still works, but it's deprecated. Use `call_get_bulk`.

## Update

Send the call's `name` and the fields you want to change:

```bash title="Request"
curl -X PUT "$BASE_URL/api/method/tatva_connect.api.partner_call.call_update" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "PARTNER-3f9a1c7e2b",
    "duration": 187
  }'
```

- Only the fields you send change.
- To move the call to another lead, send `lead` or `mobile_no`. An update never matches a lead by the call's phone numbers.

## Delete

Send the call's `name` to `call_delete`, in the query:

```bash title="Request"
curl -X DELETE "$BASE_URL/api/method/tatva_connect.api.partner_call.call_delete?name=PARTNER-3f9a1c7e2b" \
  -H 'Authorization: token <api_key>:<api_secret>'
```

If the call has linked records, the API returns `409 cannot_delete`.

## Bulk

Each bulk write handles up to 25 calls, and `call_get_bulk` up to 200. `call_schema` reports these limits in `bulk.max_per_call` and `bulk.max_per_read`.

| Call | Body key |
|---|---|
| `call_create_bulk` | `calls` |
| `call_update_bulk` | `updates`, each with its own `name` |
| `call_delete_bulk` | `names` |
| `call_get_bulk` | `names` |

The API handles each call on its own. The response has a `summary` with the counts, and a `results` array with one entry per call, in the order you sent them. Resend only the ones that failed. By default, a key can make one bulk write every 5 seconds. Bulk reads don't wait for it.

## Rules

| Topic | What to know |
|---|---|
| Linking | Send `lead` when you know it. A call matched by phone number is linked only when exactly one lead matches. |
| Unlinked calls | A call saved without a lead can't be read with your key. |
| Direction | Send `Inbound` or `Outbound`. Any other value returns `400`. |
| Recording | Send the recording as a link in `recording_url`. The API doesn't accept the audio file itself. |
| Time | On create, `started_at` also sets `creation`, so calls you send late still sort in the right order. |
| Rate limits | See [Rate limits](/rate-limits) for the default limits, and how to ask for more. |

## Errors

These are the errors you're most likely to see with calls. [Errors](/partner-errors) explains the error format.

| Status | Code | When |
|---|---|---|
| `400` | `validation_error` | `direction`, `from_number`, or `to_number` is missing. `direction` isn't `Inbound` or `Outbound`. A value doesn't fit its type. |
| `404` | `not_found` | The call or the lead doesn't exist, or your key can't reach it. |
| `409` | `cannot_delete` | The call has linked records. |
| `409`, `422` | `conflict` | An `Idempotency-Key` is still in use, or was used with a different body. |
| `429` | `rate_limited` | Your key reached its rate limit. Wait for `retry_after` seconds. |
