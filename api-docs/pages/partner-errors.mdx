Every failed call returns the same error shape, with an HTTP status that matches it. The API never returns a stack trace or a raw framework error, even for early failures such as a bad key or invalid JSON. This page explains the shape and every error code.

## The error shape

```json title="Response"
{
  "status": "error",
  "error": {
    "code": "validation_error",
    "message": "…",
    "fields": ["mobile_no"]
  }
}
```

| Key | What it tells you |
|---|---|
| `status` | Always `error` on a failure. |
| `error.code` | What went wrong. Branch your code on this value. |
| `error.message` | An explanation for people. It can change, so don't match on its text. |
| `error.fields` | The fields that caused the error, when it's about specific fields. |
| `error.detail` | Extra facts for some errors, such as a file's scan result. |
| `error.retry_after` | For some `429` and `503` errors, the seconds to wait before you retry. |

`fields`, `detail`, and `retry_after` appear only when they apply. Read them by name, and expect them to be missing.

## Every code

| Code | Status | What it means | What to do |
|---|---|---|---|
| `validation_error` | `400` | The request broke a rule: a required field is missing, a value isn't allowed, a value doesn't fit its type, or a bulk call has too many records. | Fix the request. `error.fields` names the fields. Don't retry it unchanged. |
| `bad_request` | `400` | The request couldn't be read, for example because the JSON is invalid. | Fix the request body. |
| `unauthorized` | `401` | The `Authorization` header is malformed, or the key or secret is wrong. | Check the header format. See [Authentication](/partner-validate-key). |
| `forbidden` | `403` | There's no `Authorization` header, or the key isn't allowed to use the Partner API. | Send the header. If it's there, contact TatvaCare. |
| `not_found` | `404` | The record doesn't exist, or your key can't reach it. | Check the `name` or phone number. The API gives the same answer for both cases on purpose. |
| `conflict` | `409` | The same `Idempotency-Key` is still being processed. | Wait, then retry with the same key. |
| `conflict` | `422` | The same `Idempotency-Key` was used before with a different body or endpoint. | Use a new key for a new request. |
| `duplicate` | `409` | The record clashes with one that already exists. | Resend the same request. It finds the existing record and updates it. |
| `cannot_delete` | `409` | The record has linked records, so it can't be deleted. | Keep it, or delete the linked records first. |
| `rate_limited` | `429` | Your key reached one of its limits. | Wait `retry_after` seconds, then retry. See [Rate limits](/rate-limits). |
| `server_error` | `500` | Something went wrong on the TatvaCare side. | Retry once with the same `Idempotency-Key`. If it fails again, contact TatvaCare. |
| `server_busy` | `503` | The service is busy, or a service it depends on is unavailable. | Wait `retry_after` seconds if it's there. Otherwise, retry with a growing wait. |
| `write_conflict` | `503` | A bulk call collided with other work. Nothing was saved. | Wait `retry_after` seconds, then send the whole call again. |

## Validation errors name the field

A `validation_error` about a field names it in `error.fields`. Use it to show the problem next to the right field, or to log which value to fix:

```json title="Response"
{
  "status": "error",
  "error": {
    "code": "validation_error",
    "message": "…",
    "fields": ["custom_current_program"]
  }
}
```

When a value isn't on a field's list of allowed values, the message lists the values you can send.

## Errors in a bulk call

A bulk call returns `200` even when some records fail. Each failed record has its own error in `results`, with the same `code`, `message`, and `fields` as a single call:

```json title="Response"
{
  "status": "success",
  "summary": { "total": 2, "succeeded": 1, "failed": 1 },
  "results": [
    { "index": 0, "status": "success", "action": "created", "data": { "name": "a7f3c9e12b" } },
    { "index": 1, "status": "error", "error": { "code": "validation_error", "message": "…", "fields": ["mobile_no"] } }
  ]
}
```

Check `status` on every row of `results`. A `200` doesn't mean every record was saved. Resend only the records that failed, after you fix them.

A bulk call fails as a whole only when it can't run at all. For example, a missing body key or too many records returns `400`, and a `write_conflict` returns `503`.
