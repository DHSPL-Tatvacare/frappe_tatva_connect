Every request carries your API key in the `Authorization` header. To check that a key works, call `lead_schema` with it. The call doesn't change any data. It returns the fields the key can use.

:::warning{title="Test a key in a private window"}

If you're signed in to the TatvaCare CRM in this browser, the playground also sends your CRM session. A call without a key can then succeed here but fail from your code.

:::

:::note{title="Save a key for the playground"}

Each operation in the [API Reference](/partner-api) has a playground where you can send a real request. Paste your key below to save it in this browser. Then, in any playground, select the **Partner API key** identity to send requests with it.

:::

<ApiKeyInput />

```bash title="Request"
curl "$BASE_URL/api/method/tatva_connect.api.partner.lead_schema" \
  -H 'Authorization: token <api_key>:<api_secret>'
```

`$BASE_URL` is the address of the environment you're calling. See [Conventions](/conventions#environments).

## Check the response

| Response | Meaning | What to do |
|---|---|---|
| `200` with a `data` object | The key works. `data` lists the fields it can use. | Continue to the [Quickstart](/partner-quickstart). |
| `401` `unauthorized` | The header is malformed, or the key or secret is wrong. | Check the header format: `Authorization: token <api_key>:<api_secret>`. Use lowercase `token`, one space, and a colon between the key and the secret. See [Conventions](/conventions#authentication). |
| `403` `forbidden` | The request has no `Authorization` header, or the key can't use the Partner API. | Send the header. If it's there, check that you're using the key TatvaCare issued for the Partner API. |

A `200` response looks like this (shortened). The `data` object lists the exact fields and sections your key can use:

```json title="Response"
{
  "status": "success",
  "data": {
    "fields": [
      { "fieldname": "mobile_no", "label": "Mobile No", "type": "Data", "behavior": "REQUIRED", "required": true },
      { "fieldname": "first_name", "label": "First Name", "type": "Data", "behavior": "OPTIONAL", "required": false }
    ],
    "children": { "...": "..." },
    "routing": { "mode": "forced", "...": "..." }
  }
}
```

Each key has its own schema. Build your requests from this response, not from a field list copied from somewhere else. [Schema discovery](/discover-schema) explains the response in full.

## Keys don't expire

You send the same key and secret with every request. There's no token lifetime, no refresh call, and nothing to renew.

A key stops working only when TatvaCare disables it or changes its secret. The API then returns `401 unauthorized`. Retrying won't help. Ask TatvaCare for a new key.

The 30-minute timer in the box above applies only to this browser. The page removes a saved key after 30 minutes without use, so it isn't left on a shared computer. It doesn't affect the key itself.
