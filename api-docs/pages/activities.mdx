An activity is a form filled in against a [lead](/leads), such as a follow-up call. Each activity has a task type, and the task type decides which fields the form has.

## Operations

All activity endpoints start with `$BASE_URL/api/method/tatva_connect.api.partner_activity.` The [API Reference](/partner-api) lists every parameter and has a playground for each one.

| Operation | Method | Endpoint | What it does |
|---|---|---|---|
| Schema | `GET` | `activity_schema` | Lists the task types for a lead, and the fields of each one. |
| Get | `GET` | `activity_get` | Reads one activity by `name`. |
| List | `GET` | `activity_list` | Deprecated. Use `activity_get_bulk` with filters. |
| Create | `POST` | `activity_create` | Creates an activity on a lead. |
| Update | `PUT` | `activity_update` | Changes an activity by `name`. |
| Delete | `DELETE` | `activity_delete` | Deletes an activity by `name`. |
| Get many | `POST` | `activity_get_bulk` | Reads up to 200 activities by `name`, or a page of activities that match filters. |
| Create many | `POST` | `activity_create_bulk` | Creates up to 25 activities. |
| Update many | `PUT` | `activity_update_bulk` | Changes up to 25 activities by `name`. |
| Delete many | `DELETE` | `activity_delete_bulk` | Deletes up to 25 activities by `name`. |

## Identity

- Each activity has a **unique ID** in `name`, for example `1024`. Store it. You need it to read, update, or delete the activity.
- An activity belongs to one lead. To create one, send the lead's `name` as `lead`, or its phone number as `mobile_no`.
- The CRM doesn't check for duplicates. If you send the same create twice, you get two activities. To retry a create safely, send an `Idempotency-Key` header. See [Writes and retries](/writes-and-retries).
- `external_id` is your own label for the activity. The CRM never uses it to find an activity. See [Keywords](/keywords).

## Fields

The task types, and their fields, depend on the lead's product line and group. So `activity_schema` needs a lead. Call it with the lead to list its task types:

```bash title="Request"
curl -s "$BASE_URL/api/method/tatva_connect.api.partner_activity.activity_schema?lead=a7f3c9e12b" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  | jq -r '.data.task_types[] | "\(.label)\t\(.field_count) fields"'
```

```text title="Output"
Follow Up Call	4 fields
Welcome Call	12 fields
```

Add `task_type` to get the fields of one task type:

```bash title="Request"
curl -s "$BASE_URL/api/method/tatva_connect.api.partner_activity.activity_schema?lead=a7f3c9e12b&task_type=Follow%20Up%20Call" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  | jq -r '.data.task_types[0].fields[] | "\(.fieldname)\t\(.source)\t\(.behavior)"'
```

```text title="Output"
first_name	lead	OPTIONAL
outcome	activity	REQUIRED
callback_date	activity	OPTIONAL
remarks	activity	OPTIONAL
```

Each field is described the same way as a lead field. See [Field attributes](/discover-schema#field-attributes). Activity fields also have these attributes:

| Attribute | What it tells you |
|---|---|
| `source` | `activity` for an answer to the form. `lead` for a value the form shows from the lead. |
| `conditional` | `true` when the field isn't always on the form. |
| `shown_when` | The field is on the form only when these conditions are met. |
| `required_when` | The field is required only when these conditions are met. |
| `controlled_by` | The field's allowed values depend on the answer to this field. |

A condition is a list of rules. Here, `callback_date` is on the form, and required, when `outcome` is `Callback`:

```json title="Response"
{
  "fieldname": "callback_date",
  "label": "Callback Date",
  "type": "Date",
  "behavior": "OPTIONAL",
  "source": "activity",
  "conditional": true,
  "shown_when": {
    "any_of": [
      { "all_of": [ { "field": "outcome", "operator": "is", "value": "Callback" } ] }
    ]
  },
  "required_when": {
    "any_of": [
      { "all_of": [ { "field": "outcome", "operator": "is", "value": "Callback" } ] }
    ]
  }
}
```

Read it like this:

- `any_of` is met when any one of its entries is met. An empty `any_of` is never met, so the field is never on the form.
- `none_of` is met when none of its entries is met. It appears under `shown_when` to hide a field.
- `all_of` is met when every rule in it is met.
- Each rule compares one field with an `operator`: `is`, `is not`, `is set`, or `is not set`. Only `is` and `is not` have a `value`.

If `conditional` is `true` but there's no `shown_when`, the condition can't be listed. Send the field only when your form showed it.

You can also send `notes` under `values` when you create an activity, for free text. It comes back under `values.notes`.

## Create

Send the lead, the task type, and the answers under `values`:

```bash title="Request"
curl -X POST "$BASE_URL/api/method/tatva_connect.api.partner_activity.activity_create" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: <a-new-uuid-per-activity>' \
  -d '{
    "lead": "a7f3c9e12b",
    "task_type": "Follow Up Call",
    "external_id": "REF-2001",
    "values": {
      "outcome": "Callback",
      "callback_date": "2026-09-30",
      "remarks": "Asked for a call next week."
    }
  }'
```

```json title="Response"
{
  "status": "success",
  "action": "created",
  "data": {
    "name": "1024",
    "lead": "a7f3c9e12b",
    "task_type": "Follow Up Call",
    "status": "Done",
    "external_id": "REF-2001",
    "creation": "2026-09-23 11:02:17",
    "modified": "2026-09-23 11:02:17",
    "values": {
      "first_name": "Asha",
      "outcome": "Callback",
      "callback_date": "2026-09-30",
      "remarks": "Asked for a call next week."
    }
  }
}
```

- `task_type` takes the task type's `label`, as shown, or its `name`.
- `first_name` wasn't sent. It's a `lead` field, so the CRM saved the lead's current value.
- The CRM sets `status`. A task type with `is_logged_complete` set to `1` saves its activities as `Done`.
- If the activity happened in the past, send `creation` as `YYYY-MM-DD HH:MM:SS` in IST.

## Read and list

To read one activity, send its `name` to `activity_get`.

To read many activities, send filters to `activity_get_bulk` instead of `names`. Send the lead's `name` as `lead`, or its phone number as `mobile_no`. It returns whole activities, newest first, and adds `paging` with `total`, `count`, `offset`, `limit` and `has_more`. You can filter by:

| Filter | Returns activities |
|---|---|
| `task_type` | of this task type, by `label` or `name` |
| `status` | with this status, such as `Done` |
| `created_after`, `created_before` | created in this time range |
| `updated_after`, `updated_before` | changed in this time range |

```bash title="Request"
curl -X POST "$BASE_URL/api/method/tatva_connect.api.partner_activity.activity_get_bulk" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  -H 'Content-Type: application/json' \
  -d '{
    "lead": "a7f3c9e12b",
    "updated_after": "2026-09-01 00:00:00",
    "limit": 200
  }'
```

A page holds 20 activities by default and 200 at most. Use `limit` and `offset` to page. Dates follow [Dates and times](/conventions#dates-and-times).

`activity_list` takes the same filters and still works, but it's deprecated. Use `activity_get_bulk`.

## Update

Send the activity's `name`, and only the answers you want to change:

```bash title="Request"
curl -X PUT "$BASE_URL/api/method/tatva_connect.api.partner_activity.activity_update" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "1024",
    "values": {
      "outcome": "Connected"
    }
  }'
```

```json title="Response"
{
  "status": "success",
  "action": "updated",
  "data": {
    "name": "1024",
    "lead": "a7f3c9e12b",
    "task_type": "Follow Up Call",
    "status": "Done",
    "external_id": "REF-2001",
    "creation": "2026-09-23 11:02:17",
    "modified": "2026-09-25 09:15:04",
    "values": {
      "first_name": "Asha",
      "outcome": "Connected",
      "remarks": "Asked for a call next week."
    }
  }
}
```

- Answers you don't send stay as they are.
- `callback_date` is gone. The new `outcome` hides it, so the CRM dropped its answer.
- You can change the task type. You can't move an activity to another lead.

## Delete

Send the activity's `name` to `activity_delete`, in the query:

```bash title="Request"
curl -X DELETE "$BASE_URL/api/method/tatva_connect.api.partner_activity.activity_delete?name=1024" \
  -H 'Authorization: token <api_key>:<api_secret>'
```

If the activity has linked records, the API returns `409 cannot_delete`.

## Bulk

Each bulk write handles up to 25 activities, and `activity_get_bulk` up to 200. `activity_schema` reports these limits in `bulk.max_per_call` and `bulk.max_per_read`.

| Call | Body key |
|---|---|
| `activity_create_bulk` | `activities` |
| `activity_update_bulk` | `updates`, each with its own `name` |
| `activity_delete_bulk` | `names` |
| `activity_get_bulk` | `names` |

The API handles each activity on its own. The response has a `summary` with the counts, and a `results` array with one entry per activity, in the order you sent them. Resend only the ones that failed. By default, a key can make one bulk write every 5 seconds. Bulk reads don't wait for it.

## Rules

| Topic | What to know |
|---|---|
| Task types | A lead offers only the task types of its product line and group. Sending another one returns `400`. |
| Hidden fields | Send only the fields your answers put on the form. On create, a value for a field that isn't on the form returns `400`. On update, the API doesn't save it, or `notes`. |
| Required fields | A field can be required always, or only when `required_when` is met. |
| Allowed values | For a field with a fixed list, send one of its `allowed_values`. |
| Lead fields | The API saves a `lead` field on the activity. If your answer changes it, the API also updates the lead, as a rep's form does. |
| Filled fields | Some fields are filled by the form from another answer. The form's value replaces yours. |
| Files | To attach a file to an activity, send the activity's `name` as `activity` to `file_attach`. See [Files](/files). |
| Rate limits | See [Rate limits](/rate-limits) for the default limits, and how to ask for more. |

## Errors

These are the errors you're most likely to see with activities. [Errors](/partner-errors) explains the error format.

| Status | Code | When |
|---|---|---|
| `400` | `validation_error` | No lead was sent. `task_type` is missing, or the lead doesn't offer it. A required field is missing, a value isn't allowed or doesn't fit, or a field isn't on the form. An in-person task type needs a location captured on the rep's device. |
| `404` | `not_found` | The activity or the lead doesn't exist, or your key can't reach it. An unknown `task_type` in `activity_schema` also returns this. |
| `409` | `cannot_delete` | The activity has linked records. |
| `409`, `422` | `conflict` | An `Idempotency-Key` is still in use, or was used with a different body. |
| `429` | `rate_limited` | Your key reached its rate limit. Wait for `retry_after` seconds. |
