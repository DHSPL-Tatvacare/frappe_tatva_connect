Every change to the Partner API, newest first. An entry marked <Badge variant="destructive">Breaking</Badge> changes a response that an existing integration already reads, so it needs action.

<div className="changelog">
<Stepper>

1. **2026-09-26** <Badge variant="destructive">Breaking</Badge>

   **Ticket status moves can follow helpdesk rules**

   Once the helpdesk sets rules for moving a ticket's `status`, a move they don't allow returns `400`. A move they keep for a role returns `403`. Until then, `status` changes as before.

1. **2026-09-26**

   **Tickets have a sub type and a source**

   Every ticket returns `ticket_sub_type` and `ticket_source`, and you can send and filter by both. A `ticket_sub_type` that doesn't belong to the ticket's `ticket_type` returns `400`.

1. **2026-09-25** <Badge variant="destructive">Breaking</Badge>

   **Schema fields use `behavior` and `allowed_values` only**

   Every `*_schema` field drops `required` and `options`. Read `behavior` to know what to send, and `allowed_values` for the values you can send. A new `behavior`, `IMMUTABLE`, marks a field you send only on create.

1. **2026-09-25** <Badge variant="destructive">Breaking</Badge>

   **Refusals name the field you sent**

   A filter date the API can't read, such as `created_after=banana`, returns `400 validation_error` instead of every record. On leads and activities, a value outside a `Select` field's list names the field in `error.fields`. An unknown `name` on `lead_update`, `lead_delete` or `deal_get` returns `fields: ["name"]` instead of `["lead"]`. Sending neither `name` nor `mobile_no` returns `fields: ["name", "mobile_no"]`.

1. **2026-09-25** <Badge variant="destructive">Breaking</Badge>

   **Activity answers follow the schema**

   An activity answer outside a field's `allowed_values` returns `400 validation_error`, naming the field. It used to be saved as sent. Number answers, such as an age, now read back as numbers instead of text, and `Check` answers as `0` or `1`.

1. **2026-09-24** <Badge variant="destructive">Breaking</Badge>

   **`created_at` is now `creation`**

   Notes, tickets and comments no longer return `created_at`. To backdate an activity or a note, send `creation`. The API ignores a `created_at` you still send.

1. **2026-09-24**

   **Every `*_get_bulk` accepts filters, and lists are deprecated**

   Send filters instead of `names` to read a page of whole records. Every record except a lead now returns `creation` and `modified`. A lead returns them when `lead_schema` lists them. Every `*_list` still works, but it's deprecated. Use the matching `*_get_bulk`.

1. **2026-09-24**

   **Bulk reads take up to 200 records and don't wait**

   Every `*_get_bulk` call now accepts up to 200 `names`. `lead_schema` reports this in `bulk.max_per_read`. Bulk reads, lists and bulk job results no longer wait for the 5-second limit, which now applies to bulk writes only.

1. **2026-09-24**

   **`lead_get_bulk` accepts filters**

   Send the `lead_list` filters to `lead_get_bulk` without `names` or `mobile_nos`. It returns a page of whole leads, with their sections, and a `paging` object. See [Read and list](/leads#read-and-list).

1. **2026-09-24**

   **Leads can be updated and deleted by phone number**

   `lead_update` and `lead_delete` accept `mobile_no` when you send no `name`. `lead_update_bulk` accepts it in each item, and `lead_delete_bulk` accepts `mobile_nos`.

1. **2026-09-15**

   **Rows can be added to a section without a key**

   The API used to refuse a row sent without its key. Now the CRM adds it and sets its key to the time it arrived. To delete a row, you still send its key.

1. **2026-09-14** <Badge variant="destructive">Breaking</Badge>

   **Calls use `started_at` instead of `start_time`**

   A call's start time used to be `start_time`. It's now `started_at` in every call you send and read, and `start_time` no longer exists. Rename the field in your integration. If you imported the Postman collection before this date, download it again.

1. **2026-09-14**

   **Bulk job errors return a clean error body**

   A refused bulk job request used to return a stray `"message": true` next to the error. It now returns only the standard [error shape](/partner-errors).

1. **2026-09-11**

   **Activity forms can be discovered**

   `activity_schema` now lists the fields each task type requires, the fields that depend on other answers, and the conditions they depend on. You can build activity requests from the response instead of guessing.

1. **2026-09-10**

   **Paging is stable**

   Two records with the same sort value could appear on two pages, or on neither. Every list now sorts on a unique value last, so page boundaries don't move.

1. **2026-09-06**

   **Simultaneous creates return `409 duplicate`**

   When two requests created the same lead at the same moment, the slower one used to get `400 validation_error`, as if its request were wrong. It now gets `409 duplicate`, and a retry reaches the lead that already exists.

1. **2026-08-25**

   **Values that aren't allowed are refused**

   The API used to drop a value that wasn't on a field's list, and still return `200`. The call now returns `400`, names the field, and lists the values you can send. Read the allowed values from [`lead_schema`](/discover-schema).

1. **2026-08-25**

   **The screening section and `custom_substage` can be granted**

   Your key can now be given the screening section and `custom_substage`. `lead_schema` lists them when your key has them.

1. **2026-08-24**

   **You can send your own `source`**

   When your key doesn't set a `source`, you can now send one. The API used to drop it. The CRM adds a source it hasn't seen before. A key that sets a `source` still uses its own.

1. **2026-08-14**

   **Deals can be read and updated**

   `deal_get` and `deal_update` read and change a lead's deal, using the lead's `name`. The CRM records the deal when a lead converts, so there's no create or delete. See [Deals](/deals).

1. **2026-08-12**

   **The program can be left out on create for some keys**

   For a key in `list` mode that allows it, you can leave out `custom_current_program` when you create a lead. The CRM sets it later. `lead_schema` shows whether this applies in `routing.program_required`.

1. **2026-08-04**

   **File links you can use, and readable values**

   `file_url` is now a signed link, returned with `expires_at` and `size`. `attached_to` uses the same words that `file_attach` accepts. Fields that stored internal codes, including `task_type`, now return readable labels. A field can also hold several values from its list.

1. **2026-08-03**

   **Field types are checked**

   The API used to accept a value of the wrong type and convert it silently. The API now refuses it with `400` and names the field. Send each value in the `type` that `lead_schema` gives for its field.

</Stepper>
