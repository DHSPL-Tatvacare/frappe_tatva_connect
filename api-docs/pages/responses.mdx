Every response is JSON, with the same few shapes on every endpoint. This page shows each shape and how to read values from it.

## Read every response the same way

1. Check `status`. It's `success` or `error`.
2. On `success`, read `action` to see what happened, then read the data.
3. On `error`, read `error.code`. See [Errors](/partner-errors).

The values sit at the top level of the body. There's no wrapper to remove.

## One record

Reads and writes of one record return the record under `data`:

```json title="Response"
{
  "status": "success",
  "action": "created",
  "data": {
    "name": "a7f3c9e12b",
    "mobile_no": "+919900000000",
    "first_name": "Asha"
  }
}
```

`action` is one of:

| `action` | Returned by |
|---|---|
| `created` | A create that made a new record. |
| `updated` | An update, or a `lead_create` that found an existing lead. |
| `fetched` | A read, a list, or a schema call. |
| `deleted` | A delete. `data` then holds only `{ "name": "…" }`. |

A create or an update returns the whole record as your key can read it. You don't need to read it back.

## A list

A list returns one page under `data`:

```json title="Response"
{
  "status": "success",
  "action": "fetched",
  "data": {
    "total": 240,
    "count": 20,
    "offset": 0,
    "limit": 20,
    "has_more": true,
    "leads": [
      { "name": "a7f3c9e12b", "…": "…" }
    ]
  }
}
```

| Key | What it tells you |
|---|---|
| `total` | How many records match your filters. |
| `count` | How many records are on this page. |
| `offset`, `limit` | Where this page starts, and the page size. |
| `has_more` | `true` if there's another page. Ask for it with `offset` set to `offset + count`. |

The records are under the resource's plural name: `leads`, `activities`, `calls`, `notes`, `files`, `tickets`, or `comments`.

## A bulk call

A bulk call returns `200`, even when some records fail. It has a `summary` and one `results` entry per record:

```json title="Response"
{
  "status": "success",
  "summary": { "total": 2, "succeeded": 1, "failed": 1 },
  "results": [
    { "index": 0, "status": "success", "action": "created", "data": { "name": "a7f3c9e12b" } },
    { "index": 1, "status": "error", "error": { "code": "validation_error", "message": "…", "fields": ["mobile_no"] } }
  ]
}
```

- `results` is in the order you sent the records. `index` is the record's position, starting at `0`.
- Each entry has its own `status`. Check it on every entry.
- A saved record's `name` is at `results[i].data.name`.
- A failed record's error is at `results[i].error`, in the same shape as a [single error](/partner-errors).

[Bulk job](/async-bulk#read-the-results) results use a different, flat shape.

## Read a value by its path

Read a value by following its path from the top of the body:

| Value | Path |
|---|---|
| Whether the call worked | `status` |
| What happened | `action` |
| The record's `name` | `data.name` |
| A lead field | `data.first_name` |
| A field in a section row | `data.custom_lab_profile[0].hba1c` |
| The error code | `error.code` |
| The third record in a bulk call | `results[2].status`, `results[2].data.name` |

Section rows come back in the order the CRM stores them. Don't assume `[0]` is the newest. To find a row, match its `key_field`, such as `report_date`. See [Sections](/discover-schema#sections).

This example reads the latest `hba1c` from a lead, by picking the row with the latest `report_date`:

```bash title="Request"
curl -s "$BASE_URL/api/method/tatva_connect.api.partner.lead_get?name=a7f3c9e12b" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  | jq '.data.custom_lab_profile | max_by(.report_date) | .hba1c'
```

The same in code, with the full check on `status`:

<CodeTabs>

```python title="Python"
import os
import requests

BASE_URL = os.environ["BASE_URL"]
r = requests.get(
    f"{BASE_URL}/api/method/tatva_connect.api.partner.lead_get",
    headers={"Authorization": "token <api_key>:<api_secret>"},
    params={"name": "a7f3c9e12b"},
)
body = r.json()

if body["status"] == "success":
    labs = body["data"].get("custom_lab_profile", [])
    latest = max(labs, key=lambda row: row["report_date"]) if labs else None
    print(latest["hba1c"] if latest else None)
else:
    print(body["error"]["code"], body["error"]["message"])
```

```typescript title="TypeScript"
const BASE_URL = process.env.BASE_URL;
const res = await fetch(
  `${BASE_URL}/api/method/tatva_connect.api.partner.lead_get?name=a7f3c9e12b`,
  { headers: { Authorization: "token <api_key>:<api_secret>" } },
);
const body = await res.json();

if (body.status === "success") {
  const labs = body.data.custom_lab_profile ?? [];
  const latest = labs.reduce((a, b) => (!a || b.report_date > a.report_date ? b : a), null);
  console.log(latest ? latest.hba1c : null);
} else {
  console.log(body.error.code, body.error.message);
}
```

</CodeTabs>

A field your key can't use isn't in the response. If you sent a field and it's missing from the response, the CRM didn't save it. Check your fields against [`lead_schema`](/discover-schema).
