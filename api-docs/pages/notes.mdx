A note is free text added to a [lead](/leads), such as a summary of a conversation. Use notes for anything that doesn't fit a field or an [activity](/activities) form.

## Operations

All note endpoints start with `$BASE_URL/api/method/tatva_connect.api.partner_note.` The [API Reference](/partner-api) lists every parameter and has a playground for each one.

| Operation | Method | Endpoint | What it does |
|---|---|---|---|
| Schema | `GET` | `note_schema` | Lists the note fields. |
| Get | `GET` | `note_get` | Reads one note by `name`. |
| List | `GET` | `note_list` | Deprecated. Use `note_get_bulk` with filters. |
| Create | `POST` | `note_create` | Adds a note to a lead. |
| Update | `PUT` | `note_update` | Changes a note by `name`. |
| Delete | `DELETE` | `note_delete` | Deletes a note by `name`. |
| Get many | `POST` | `note_get_bulk` | Reads up to 200 notes by `name`, or a page of notes that match filters. |
| Create many | `POST` | `note_create_bulk` | Adds up to 25 notes. |
| Update many | `PUT` | `note_update_bulk` | Changes up to 25 notes by `name`. |
| Delete many | `DELETE` | `note_delete_bulk` | Deletes up to 25 notes by `name`. |

## Identity

- Each note has a **unique ID** in `name`, for example `n4b8c2d6e1`. Store it. You need it to read, update, or delete the note.
- A note always belongs to a lead. To create one, send the lead's `name` as `lead`, or its phone number as `mobile_no`.
- The CRM doesn't check for duplicates. If you send the same create twice, you get two notes. To retry a create safely, send an `Idempotency-Key` header. See [Writes and retries](/writes-and-retries).
- `external_id` is your own label for the note. The CRM never uses it to find a note. See [Keywords](/keywords).

## Fields

`note_schema` lists the note fields. They're the same for every key:

```bash title="Request"
curl -s "$BASE_URL/api/method/tatva_connect.api.partner_note.note_schema" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  | jq -r '.data.fields[] | "\(.fieldname)\t\(.behavior)"'
```

| Field | What it holds |
|---|---|
| `lead` | The lead's `name`. |
| `mobile_no` | The lead's phone number, used only to find the lead. |
| `content` | The note's text, as HTML or plain text. Required. |
| `title` | A short title, up to 140 characters. |
| `creation` | When the note was written, as `YYYY-MM-DD HH:MM:SS` in IST. Only on create. |
| `external_id` | Your own label for the note. |

## Create

```bash title="Request"
curl -X POST "$BASE_URL/api/method/tatva_connect.api.partner_note.note_create" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: <a-new-uuid-per-note>' \
  -d '{
    "lead": "a7f3c9e12b",
    "external_id": "NOTE-001",
    "title": "Missed callback",
    "content": "<p>Asha called back while the line was busy. Call her again on 30 Sep.</p>",
    "creation": "2026-09-21 16:20:00"
  }'
```

```json title="Response"
{
  "status": "success",
  "action": "created",
  "data": {
    "name": "n4b8c2d6e1",
    "external_id": "NOTE-001",
    "lead": "a7f3c9e12b",
    "title": "Missed callback",
    "content": "<p>Asha called back while the line was busy. Call her again on 30 Sep.</p>",
    "creation": "2026-09-21 16:20:00",
    "modified": "2026-09-24 10:02:11"
  }
}
```

If you don't send a `title`, the CRM sets one. It's "Note added on" plus the date when you send `creation`, and "Note" otherwise. For example, a note sent with `creation` `2026-09-22 10:00:00` and no title gets "Note added on 22 Sep 2026".

## Read and list

To read one note, send its `name` to `note_get`.

To read many notes, send filters to `note_get_bulk` instead of `names`. Send the lead's `name` as `lead`, or its phone number as `mobile_no`. It returns whole notes, newest first, and adds `paging` with `total`, `count`, `offset`, `limit` and `has_more`. You can filter by:

| Filter | Returns notes |
|---|---|
| `created_after`, `created_before` | created in this time range |
| `updated_after`, `updated_before` | changed in this time range |

```bash title="Request"
curl -X POST "$BASE_URL/api/method/tatva_connect.api.partner_note.note_get_bulk" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  -H 'Content-Type: application/json' \
  -d '{
    "lead": "a7f3c9e12b",
    "updated_after": "2026-09-01 00:00:00",
    "limit": 200
  }'
```

A page holds 20 notes by default and 200 at most. Use `limit` and `offset` to page. Dates follow [Dates and times](/conventions#dates-and-times).

`note_list` takes the same filters and still works, but it's deprecated. Use `note_get_bulk`.

## Update

Send the note's `name` and the fields you want to change:

```bash title="Request"
curl -X PUT "$BASE_URL/api/method/tatva_connect.api.partner_note.note_update" \
  -H 'Authorization: token <api_key>:<api_secret>' \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "n4b8c2d6e1",
    "content": "<p>Asha called back while the line was busy. Callback booked for 30 Sep.</p>"
  }'
```

- Only the fields you send change.
- You can't make `content` empty.
- To move the note to another lead, send `lead` or `mobile_no`.

## Delete

Send the note's `name` to `note_delete`, in the query:

```bash title="Request"
curl -X DELETE "$BASE_URL/api/method/tatva_connect.api.partner_note.note_delete?name=n4b8c2d6e1" \
  -H 'Authorization: token <api_key>:<api_secret>'
```

If the note has linked records, the API returns `409 cannot_delete`.

## Bulk

Each bulk write handles up to 25 notes, and `note_get_bulk` up to 200. `note_schema` reports these limits in `bulk.max_per_call` and `bulk.max_per_read`.

| Call | Body key |
|---|---|
| `note_create_bulk` | `notes` |
| `note_update_bulk` | `updates`, each with its own `name` |
| `note_delete_bulk` | `names` |
| `note_get_bulk` | `names` |

The API handles each note on its own. The response has a `summary` with the counts, and a `results` array with one entry per note, in the order you sent them. Resend only the ones that failed. By default, a key can make one bulk write every 5 seconds. Bulk reads don't wait for it.

## Rules

| Topic | What to know |
|---|---|
| Content | Send HTML or plain text. The CRM removes unsafe HTML when it saves the note. |
| Title | A title longer than 140 characters is cut to 140. |
| Time | `creation` sets when the note was written, so notes you send late still sort in the right order. |
| Files | To attach a file to a note, send the note's `name` as `note` to `file_attach`. See [Files](/files). |
| Rate limits | See [Rate limits](/rate-limits) for the default limits, and how to ask for more. |

## Errors

These are the errors you're most likely to see with notes. [Errors](/partner-errors) explains the error format.

| Status | Code | When |
|---|---|---|
| `400` | `validation_error` | No lead was sent. `content` is missing or empty. A value doesn't fit its type. |
| `404` | `not_found` | The note or the lead doesn't exist, or your key can't reach it. |
| `409` | `cannot_delete` | The note has linked records. |
| `409`, `422` | `conflict` | An `Idempotency-Key` is still in use, or was used with a different body. |
| `429` | `rate_limited` | Your key reached its rate limit. Wait for `retry_after` seconds. |
